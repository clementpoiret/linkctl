# linkctl 1.0.2

`linkctl` 1.0.2 is a performance-focused patch release that reduces idle power use, avoids unnecessary media work,
and replaces repeated device polling and discovery where event-driven or cached operation is sufficient.

## Performance improvements

- An enabled `linkd` now blocks on IPC without opening the camera or building a GStreamer graph while no persistent
  recording or virtual output is active. The last persistent consumer releases the graph and media lease immediately.
- Recording and virtual-output branches are attached and detached without restarting the shared physical source.
  Recording-only operation gates raw decode, while dormant snapshot branches stop before their queues and encoders.
- Automatic H.264 and MJPEG decode prefers a usable VA-API render node and falls back to software. Operators can force
  software or VA-API decode and can pin a render node for predictable power and GPU selection.
- One-shot commands cache USB discovery, XU watches reuse their selected session, relevant USB devices alone receive
  descriptor hydration, and V4L2 control watches consume kernel events directly when available.

## Fixes

- `LINKCTL_DAEMON_SOCKET`, `LINKCTL_DECODER`, and `LINKCTL_DECODER_DEVICE` are recognized as runtime-only environment
  settings instead of being rejected as unknown persistent configuration fields.

## Compatibility and upgrade

This release does not change machine-output schema 1, daemon protocol 1, configuration formats, or vendor-profile
formats. No migration is required. The default decoder policy remains portable: it uses a suitable VA-API decoder when
one is usable and otherwise falls back to software.

See the [daemon guide](../daemon.md), [user guide](../user-guide.md), [1.0.1 release notes](v1.0.1.md), and
[security policy](../../SECURITY.md) for operational details and safety boundaries.
