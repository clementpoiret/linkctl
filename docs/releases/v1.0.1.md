# linkctl 1.0.1

`linkctl` 1.0.1 is a patch release that fixes the packaged GStreamer runtime and makes aggregate camera-native
capability reporting resilient to controls with different stream-state requirements.

## Fixes

- The Nix wrappers for `linkctl` and `linkd` now use one complete, version-consistent GStreamer plugin path containing
  the pinned core, base, good, bad, and libav plugins. An incompatible `GST_PLUGIN_SYSTEM_PATH_1_0` inherited from a
  desktop session can no longer override or contaminate the packaged runtime.
- `linkctl doctor` now reports the GStreamer version and verifies the `v4l2src`, `capsfilter`, and `fakesink` elements
  required by temporary camera-native status streams.
- `linkctl caps all` now reads passive and open-stream camera-native values in separate batches. If one batch cannot be
  prepared, the command still returns the capability map and leaves only the affected current values unset.

## Compatibility and upgrade

This release does not change machine-output schema 1, daemon protocol 1, configuration formats, or vendor-profile
formats. No migration is required. Nix users should rebuild or reinstall the package to receive the corrected wrappers;
other package formats receive the improved diagnostics and aggregate capability reads normally.

The fixes were verified with the packaged GStreamer 1.26.11 runtime and a connected Insta360 Link 2C Pro. The five
status commands affected by the missing core elements completed successfully, and `caps all` returned all 37 semantic
capabilities while matching the direct `mode compatibility status` value.

The safety and feature boundaries documented for 1.0.0 are unchanged. See the [user guide](../user-guide.md),
[compatibility matrix](../compatibility.md), [1.0.0 release notes](v1.0.0.md), and
[security policy](../../SECURITY.md) for details.
